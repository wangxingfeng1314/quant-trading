# 第三批：P0 数据止血 + P1 撮合正确性（v0.4.5）

上一轮审查发现这批问题与之前的「方法论/性能」性质不同：是**真实库里已经发生的数据污染**和**会改写回测结论的正确性 bug**。全程先复现再改，改动后实测验证。

## P0-① 除权断层误判 → 清库 → 历史不可逆丢失

四个环节串起来才造成后果：
1. `check_split_dividend_anomaly` 只用 `pct_chg` 反推前收 `implied = close/(1+pct_chg/100)`；字段缺失/填 0 时 `implied == close`，**任意涨跌 >8% 都被判成除权**
2. 误判后 `clear_daily` 立即提交 DELETE，无事务无快照
3. 全量重拉失败时 `df` 仍是原增量，却照样 `save_daily` 写回（5 行 → 1 行）
4. `full_start` 写死回溯 730 天，库里 `601318.SH` 存着 2015 年起 2880 行，触发一次永久丢掉前 3 年

修复：
- 判定改**多证据分级**：① 重叠交易日同日收盘价（最可靠，与 pct_chg 无关）② pct_chg 可信（非空非 0、|值|≤31）时反推 ③ 不可信时仅当两日期为相邻交易日（自然日差 ≤10）且涨幅超过板块涨跌停上限 +2pct 才判。**宁可漏判不可误判**
- 关键坑：有重叠且完全一致时**不能提前 return False** —— 新增日期仍可能跨越除权日，必须继续走证据 2/3（第一版写错过，实测发现后改）
- 新增 `data/storage.py::replace_daily()`：校验（新数据 ≥ 旧 90%、起点不晚于旧起点）→ 备份 `data/backups/`（压缩 CSV，留 3 份）→ DELETE+INSERT 单事务
- 新增 `services/data_service.py::resync_full_history()`：起点取 `get_earliest_date()`，只有拉取+清洗+校验全过才动库；失败整次放弃，绝不写回断裂数据
- `services/data_service.py` / `scripts/init_data.py` 统一改走新入口，移除 `clear_daily` 直接调用

## P0-② 成交量单位污染（真实库已修复）

根因：`clean_daily` 用**前复权 close** 做 `ratio = amount/(close×volume)` 分母，而 volume/amount 是未复权原值，比值随复权因子 f 阶梯漂移（601318.SH 分年中位从 293 降到 106）。逐行阈值 1.5 让同一批数据一部分 ×100、一部分不动。

真实库实锤：13 只标的中 12 只 `vwap/close≈1`（股），只有 `601318.SH` ≈131（手）；2026-07-31 单日跳变 **99.69 倍**，2015–2025 共 2812 行（97.6%）单位不一致。

修复：
- `clean_daily` 改**整批一次决策**（ratio 中位数，阈值 `LOTS_RATIO_THRESHOLD=20`，远离 f 取值域），新增 `volume_unit="auto"/"shares"/"lots"` 显式声明
- 新增 `data/storage.py::align_volume_unit()`：落库前对齐历史口径，防数据源切换产生新断层
- 新增 `scripts/repair_volume_units.py`：默认 dry-run，`--apply` 才写库，SQLite backup API 备份 + 幂等。dry-run 精准命中 601318.SH 2812 行，其余 12 只（含 ETF 巨量跳变、复权因子漂移）均未误判
- **已执行修复**，备份：`data/backups/quant_before_volume_repair_20261112_114001.db`（12.7MB）。修复后 100 倍级跳变 0 天，`vwap/close` 中位 1.314（f 漂移，正常）

## P1 撮合正确性

- **ATR 仓位未来函数**：`next_open` 在 D+1 开盘撮合，`_calc_buy_budget` 却读 D+1 的 `close`/`atr14`。改为只用信号日（D 日）数据。实测只改 D+1 收盘价：买入股数从 2700/1100/4000/600 → 全部一致
  - 排查教训：第一次构造把变化放在 D+2，误以为「未复现」，核对索引后才确认是测试数据错，不是 agent 误报
- **封板判定退化**：`is_limit_*_locked` 的 `low_price/high_price` 参数在 `portfolio.py` 出现 **0 次**，退化成「委托价等于涨跌停价就拒单」。现从 K 线传 `bar_low/bar_high`，只有一字板才拒单。真实库 18330 根 K 线中 41 天原本被误杀
- **涨跌停价舍入**：Python `round` 银行家舍入 vs 交易所 `ROUND_HALF_UP`。1.00~200.00 逐分扫描原有 **769 个价位差 1 分**（2.05 → 1.84/2.25，应为 1.85/2.26），会把成交价 clamp 到低于跌停价。改用 `Decimal` + `_exchange_round()`，现 0 偏差
- **风控克隆丢配置**：`_clone_risk_manager` / `grid_search` 的手工复制只带 4 个参数，`enable_break_even` 等 3 项被静默重置（训练段开保本止损、验证段关闭）。统一到 `engine/risk_manager.py::clone_risk_manager()`，复制 7 字段且状态独立
- **撮合规则不透传**：`grid_search` / `grid_search_parallel` / `walk_forward` / `parameter_stability` 把 `position_sizing`、`max_active_positions`、`risk_per_trade`、`market_regime_filter`、`market_index` 留在默认值。新增 `BACKTEST_OPTION_KEYS` + `build_backtest_options()` + `_options_kwargs()` 统一透传
  - UI 新增共用控件 `_render_backtest_options(prefix)`，参数优化/样本外验证两个 Tab 各一份
  - `services/backtest_service.py::run_grid_search` 同步支持
  - `grid_search_parallel` 顺带改为 worker `initializer` 注入预加载数据（8 元组 args），不再逐任务 pickle 整份行情字典；`_execute_single_grid_combo` 保留 7/9 元组向后兼容

## 环境注意

- `app/main.py` 启动时同步调 `schtasks.exe`，在本沙箱被黑名单拦截（提示不要绕过）。已被容错捕获，AppTest/测试均不受影响，但这是测试套件耗时波动（24s~60s）的根因
- Windows 上用 `py - <<'PY'` heredoc 跑含 `ProcessPoolExecutor` 的脚本会报 `OSError: <stdin>`（spawn 无法重导入 __main__）。改用 `py -c "..."` 或写成临时 .py 文件 + main guard
